# Teacher workflows and Zunis

## Tools beside question editing

The teacher orb stays above question review and inside the active native dialog's top layer. Calculator and GeoGebra quick actions, and the saved tool sequence, open a movable/resizable auxiliary window without navigation. Minimize preserves the mounted tool; restore it from the orb. Escape in an orb tool minimizes it before closing the underlying question. Question drafts stay open. Favorites, order, orb position, writing drafts, AI configuration and exam data remain keyed to the teacher account.

Questions, options and explanations use an offline [MathLive visual editor](https://mathlive.io/mathfield/guides/react/) with bundled fonts. Teachers edit actual fractions, powers and equations; LaTeX remains an internal storage format. GeoGebra's question panel typesets math too. Manual drawing works without AI. **اقتراح رسم للسؤال** tries the selected AI provider with its actual installed model and key. If generation fails, bounded local arithmetic can plot polynomial equations and multiple curves such as `y=3x+4` and `y=x²+3x+4`. The interface identifies local fallback. Other unsupported constructions remain editable manually with a safe error. Opening the editor does not send an automatic generation request. Exports are saved only after explicit attachment and question save. Keyboard focus behavior follows the [GeoGebra app parameters](https://geogebra.github.io/docs/reference/en/GeoGebra_App_Parameters/).

## Teacher grade assignments

Open **الإعدادات → حسابات المعلمين** as administrator. Select actual class/section pairs from the stored student roster, with live student counts, when creating a teacher or using **إسناد الصفوف**. No grade catalog is fabricated. With no students the selector shows an empty state directing the administrator to add/import the roster. Unknown or stale class IDs are rejected by the backend. New teachers have no class access until assigned. During upgrade existing teachers retain only their recorded student classes; the administrator can revise them. Administrators retain all classes. Databases remain private per teacher; assignment does not silently move or duplicate student credentials between teachers.

Server checks apply to student creation, CSV/Excel imports, exam reads/writes/publishing, attempts and the live lab. Grade and section aliases are normalized together. Removing access hides records without deleting them. Changes are refused while a student's attempt is in progress. Backup/restore refuses unassigned-class content, including an existing hidden record, rather than deleting or exporting it. `tests/teacher-assignments.test.ts` covers backend enforcement and persistence; `npm run test:desktop:teacher-overlay` checks the native tool and assignment UI.

The blue identity now has soft mint, lavender and warm accents. The left floating orb contains three tabs: **لهذه الصفحة**, **مساري**, and **المحادثة**. Suggestions and workflow controls no longer add banners, large decorative orbs or step labels to the page. The tools catalog keeps favorites, subject filters, custom ordering and every tool. The exam blueprint opens in a compact window with colored rows and an optional explanation.

Inside the orb, the saved tool sequence supports drag/drop from the catalog or within the sequence, plus arrow/select controls. Preferences remain validated and stored per teacher in `/api/workspace`. Opening a tool does not claim it has been completed. GeoGebra images and equation text still transfer to question drafts. The context tab shows actual tenant-scoped counts from `/api/workspace/summary`, refreshed after mutations and every ten seconds only while that tab is open. The chat tab retains AI actions, voice input and readback. No additional features are shown in student exams.

## Student roster

Open **الطلاب والصفوف → استيراد Excel أو CSV**. Drop an `.xlsx` or UTF-8 `.csv`, choose fallback class/section, preview, resolve row errors, then confirm. Arabic/English headers are detected, including a title row before the headers; sheets and columns can be selected manually. Supported fields are name, national number, optional school student ID, class and section. National numbers must be ten digits, Arabic/Persian digits are normalized, and leading zeros must be stored as text in Excel. Old `.xls` files must first be saved as `.xlsx`. Limits: 8 MB compressed, 32 MB expanded ZIP, 512 ZIP entries, 50 columns and 3000 students. Formulas are not evaluated; identity cells containing formulas are rejected. Macros, external workbook links and XML entities are rejected.

Nothing changes during preview. Preview shows masked numbers, additions, existing students and errors. Existing students are skipped by default; explicitly choose update to replace their profile/login credential. Import is atomic; invalid/duplicate IDs do not partially import. It preserves existing student IDs, exam attempts and teacher preview login codes. Students imported with national numbers use that number in the single student login field; older generated codes continue working. A national number belonging to another teacher account is rejected instead of silently linking or selecting the wrong account. Each preview is teacher-owned, single-use and valid for ten minutes. Its temporary plaintext national numbers are held only in server memory and discarded after expiry or use.

Persistent credentials use a keyed lookup and independently salted scrypt hashes, stored privately outside public student profiles. National numbers are absent from AI context, roster exports and ordinary student/session API responses. Backup includes the private credential hashes and lookup secret so restoration preserves login; it contains no plaintext national numbers. New offline recovery credentials use a random salt and PBKDF2-SHA256 (150,000 iterations); legacy code caches remain compatible. Login attempt limiting, HTTPS pinning and student password-protected logout remain in force. The school spreadsheet remains the source for recovering a forgotten national number; the app does not reveal it.

## Gemini prompt orb

In **إضافة بنك أسئلة → افتح المساعد**, the orb opens a compact editor with an expanding animation using the existing Motion library. The explicit **اقتراح تعديل عبر Gemini** action reads the teacher's encrypted Gemini key even when the main assistant is set to Ollama/OpenAI. It sends only the prompt and editing instructions. The original remains unchanged until the teacher reviews and applies the proposal; truncated/invalid responses are rejected. A proposal becomes stale if its source prompt changes. Saving updates the prompt template only; it does not import a question bank or publish anything. A valid saved Gemini key and internet are required. Provider routing and structured responses are verified with mocked upstream calls; a live paid Gemini account is not assumed by automated tests.

## Zunis

Zunis is the name/branding of the app's protection layer. Startup shows its welcome screen; the footer opens a status panel backed by `/api/security/status`, including actual server transport and existing authorization/password mechanisms. A development HTTP server is reported as HTTP. It does not display a fabricated scan, universal security guarantee or independent certification. This update also pins ExcelJS's UUID dependency to patched 11.1.1; production `npm audit --omit=dev` reported no known advisories at verification time.

## Verification

`npm test` covers roster parsing, duplicates, private credentials, real Excel roundtrip, teacher isolation, login, single-use previews, workflow persistence, Gemini-specific routing, unchanged originals and offline credential hashing. `npm run test:desktop:workflow` runs native WebView2 drag/drop, equation transfer, import preview/commit, live counts, orb navigation, prompt UI and Zunis status. Security and school-upgrade suites additionally exercise permissions, both roles, exam tools and session behavior. Test data are isolated from the school's real data.

Upstream libraries: [ExcelJS](https://github.com/exceljs/exceljs) (MIT) and existing [Motion](https://github.com/motiondivision/motion) (MIT). No remote scripts or UI libraries were added to student pages.

## Exam folders

The teacher exam list has colored folders with create/rename/recolor/delete controls, native exam-card drag/drop and an accessible move dialog on each card. Folder filters combine with status, grade and search. Deleting a folder returns its exams to Unfiled; it does not change questions, availability, results or attempts. Organization is stored independently in a tenant-scoped setting, included in existing backups. Students have no folder access. `tests/exam-folders.test.ts` checks isolation, persistence, backup inclusion, atomic moves and safe deletion; `npm run test:desktop:exam-folders` exercises the native UI.
